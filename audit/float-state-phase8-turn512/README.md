# 第八批：多上游、虚拟模型的逻辑请求四色状态

## 从上一轮继续的范围
AB入库已结束且原回执保留；本批不重复写两库。基线为5af1b457e95499861c508923ac147408efe42e2d。

## 明确的三层语义
1. **候选attempt**：提供商健康、429/503和许可各自保持原逻辑。某候选失败后另一候选成功，不点逻辑请求红灯。
2. **逻辑生成请求**：在有效路由和候选确定后begin一次，整个first候选循环结束后finish一次。健康探活、模型列表、MCP、无效输入不当成生成请求；本地限流拒绝和用户取消中立，不新增红或绿。
3. **全局显示/模型作用域**：主球显示整个网关的聚合状态，故障恢复按客户端请求的model/虚拟模型名隔离。模型A的无关成功不清模型B的故障。主MCP卫星球仍独立显示服务存活。
当前只有first顺序执行，不引入race/hedge；未来分支winner/loser取消另行设计与测试。

## 四色与状态优先级
- 蓝 `#1E88E5`：待命；没有活动逻辑请求、未解除故障或有效成功驻留。
- 橙 `#FF9800`：存在活动逻辑生成请求。不是TCP连接数，HTTP200本身不是有效生成。
- 绿 `#43A047`：具有有效生成证据的请求正常结束，且全局没有仍在忙或未解除故障，短驻留3000ms。
- 红 `#E53935`：逻辑请求的上游/协议失败；至少3000ms，之后还要同一模型作用域、故障发生后的新有效业务进展才能恢复。只有新请求、旧peer回调、角色块、usage、心跳、仅DONE不恢复。
优先级：未解除故障/红灯最低驻留 > 活动请求 > 有效成功驻留 > 待命。
若同作用域的新请求在最低红灯时间内恢复并完成，先保留红灯，再完整显示绿灯3000ms。
请求自己的数据不能清除其后来发生的失败；结束ticket和服务停启后的旧ticket无效，避免迟到回调倒灌。
状态用单调时钟，不随系统墙钟修改跳过驻留；进程/网关服务重启不保存告警，stop显式reset。
配置更新不清故障。删除有历史故障的模型也不会假装恢复，MCP返回faultScopeSample；明确停启服务可重置历史视觉告警，这不是提供商健康恢复证明。

## 有效进展与传输安全
GatewayServer在下游write+flush成功后才提交SSE观察证据；非流式要求完整响应并识别有效message后提交。内容、reasoning与工具名称/参数片段、文本/图像引用内容片段在OpenAI兼容chat结构内单独识别。
非流式最多保留256KiB用于视觉证据；超过预算继续原样转发，progressEvidenceLimited增加，不因观察逻辑截断响应、报请求失败或伪造绿色。未知格式、空content、仅角色/usage/DONE不证明生成，但不改变原HTTP业务终态。
不改路由、候选数量、模型变换、许可/重试、正文、流协议完成要求、账单语义。sent/committed后不重试、FIN半关闭等原边界继续有效。
只支持当前OpenAI兼容chat入口；音频/其他API/非标准协议的视觉适配不作已支持声明。

## 渲染与可观测性
- GatewayService为真实网关注入观察回调；后台隔离self_test创建自己的GatewayServer，不点亮真实服务主球。
- FloatingBall使用主Looper，刷新合并到最多一个待执行任务；文字与颜色来自同一次provider读取。
- 3秒状态到期单独调度，不能依赖原30秒窗口自愈watchdog。无到期转换不跑动画，不以轮询逐token重绘。
- 锁定仅限制手势/去边框，不冻结状态颜色；主球/MCP卫星球都继续更新。原makeTouchListener与拖动/解锁阈值保持原样。
- attach/解锁立即重读；detach移除本批刷新和到期回调。未重写窗口创建/权限/定位或手势。
- 原gw_debug_snapshot/runtime新增visualState：阶段、活动逻辑数、未解除/等待驻留故障数、故障代次、到期剩余、预算降级及callback错误计数，faultScopeSample最多16项，不含正文/密钥。
- 跟踪上限1024活动ticket、256故障scope；超限明确observationLimited，溢出故障保守锁存至显式reset，不为显示效果拒绝业务请求。不是无限期无损诊断存储。
